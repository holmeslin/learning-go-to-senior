# 安全實務

前作已經教過這些工具：`database/sql` 與〈[prepared statement](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter15/05_prepared_statement.html)〉、〈[`os.Root`](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter12/04_os_root.html)〉、〈[`path/filepath` 與 `io/fs`](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter12/05_filepath_fs.html)〉、〈[`math/rand/v2`](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter12/11_rand_v2.html)〉、〈[`log/slog`](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter12/10_slog.html)〉，以及〈[HTTP client](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter14/06_http_client.html)〉與〈[`httptest`](https://holmeslin.github.io/learning-go-from-zero/zh-TW/chapter14/09_httptest.html)〉。服務上線之後，缺的不是這些 API，而是判斷。實際上線時常犯同樣的錯：只檢查格式不檢查範圍與大小，JSON 解碼不限制大小、不拒絕未知欄位；把使用者輸入拼進 SQL；用 `filepath.Join` 加 `strings.HasPrefix` 檢查路徑，被 `..` 或符號連結繞過；從不檢查相依的弱點，或檢查了卻分不清哪些真的會被呼叫到；把密鑰寫在程式碼裡進版控，或在錯誤訊息與日誌裡印出來；用 `math/rand` 產生 token，TLS 設定照抄網路上關掉驗證的寫法；伺服器替使用者抓取任意網址，結果打到內網；日誌裡記了密碼、token 與完整的卡號。

這一章的主題是：Go 服務端最常見的漏洞，以及在 code review 時怎麼認出來。它不是密碼學課，不談原理，也不談驗證與授權；每一集處理一種漏洞，先讓有漏洞的寫法被實際攻擊成功，再看防線放在哪裡、擋得住什麼、擋不住什麼，因為程式這一層不是唯一的一層。有漏洞的程式碼只放在各集的 `before/`，文件註解寫明是刻意示範、不要照用，`after/` 才是可以參考的寫法。攻擊都只打本機的假東西：`httptest` 的伺服器、`t.TempDir`、記憶體裡的 SQLite；秘密一律是明顯假的值；所以 `go test` 不需要網路或外部服務，結果每次都一樣。

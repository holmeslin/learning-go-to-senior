# 錯誤設計

前作已經教過錯誤的所有機制：`error` 介面、`%w`、`errors.Is`、`errors.AsType`、`errors.Join`、`panic` 與 `recover`。會用這些工具的人，常常還是不知道該怎麼選：什麼都定義成哨兵錯誤，還是什麼都用 `fmt.Errorf` 一句帶過？要不要把底層的錯誤透出去？每一層都 log 一次嗎？

這一章把錯誤當成設計來看。函式回傳哪些錯誤、訊息怎麼寫、在哪一層處理，都是呼叫端會依賴的 API，改動它的代價和改函式簽名一樣。每一集處理一個判斷，書中出現的錯誤訊息，盡量來自會被 `go test` 逐字驗證的 `Example`。

# code review

程式碼要經過別人的眼睛才進得了主幹。這時候缺的不是平台上的按鈕，而是判斷：從第一行開始逐行挑命名與格式，看到最後才發現整個做法放錯地方；不知道 Go 程式碼該特別注意什麼，只能憑感覺；收到一個混了改名、重構與新功能的大 PR，看不完也不敢擋；意見寫成「這樣不好」，作者不知道要改什麼，也分不出哪些一定要改；送出自己的 PR 之前沒有先看過一遍，把明顯的問題留給 reviewer；分不清什麼問題值得擋下、什麼可以先放行。

這一章的主題是 review 別人的程式碼，以及準備自己的 PR 時要做的判斷。全章用同一個例子：虛構的「活動報名平台」上，作者送出一個「候補名單」PR，reviewer 依序看設計、套用檢查清單、要求拆分、寫意見、決定擋或放行，作者那一側談自我審查。例子的程式碼是真的，放在第 1 集的範例目錄，三個狀態（PR 之前、送出時、review 之後）都能編譯、跑測試；review 指出的問題用測試證明，頁面上的 diff 由那些檔案用指令產生。平台、公司與 PR 都是虛構的教材範例，文中的人一律用角色稱呼。
